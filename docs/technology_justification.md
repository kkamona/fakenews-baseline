# Technology justification

| Choice | Why |
|---|---|
| **Python 3.10+** | De-facto standard for data science and NLP; the whole thesis pipeline (pandas, scikit-learn, PyTorch, Transformers, SHAP) is Python-native, so no language boundary. |
| **pandas / NumPy** | Standard tabular and numeric tools; WELFake (~72k rows) fits in memory, so no distributed framework is needed. |
| **scikit-learn** | Mature, well-documented TF-IDF, LinearSVC, stratified splitting and metrics. `Pipeline` guarantees the vectoriser is fitted on training data only (no leakage) and makes the model one object. |
| **TF-IDF + LinearSVC** | Strong, fast, interpretable baseline for high-dimensional sparse text; coefficients enable explainability. Serves as the reference against the BERT model. |
| **matplotlib** | Standard, scriptable plotting; figures are generated by the package so they are reproducible from the CLI. |
| **Bootstrap CIs** | Model-agnostic uncertainty estimate, showing whether differences between models exceed sampling noise. |
| **src layout + pyproject.toml** | Modern packaging standard (PEP 517/621); prevents accidental imports of uninstalled code; enables `pip install -e .` and a CLI entry point. |
| **pytest + pytest-cov** | Concise tests, fixtures, parametrisation; coverage shows what is verified. |
| **ruff** | Very fast linter, enforces consistent style in CI with almost no configuration. |
| **Git + GitHub** | Version history, branching, pull requests, issue tracking; hosts CI for free. |
| **GitHub Actions** | Configured in-repo (YAML), no separate server, free for public repositories, matrix builds across Python versions. |
| **Jupyter (kept for exploration)** | Good for exploration and figures, but poor for testing and versioning, hence logic moved into modules. |
| **PyTorch + Transformers (outside CI)** | Standard for fine-tuning BERT; excluded from CI because of size and GPU needs. |
